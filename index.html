Software Configuration Management

How teams keep every piece of a software project (code, docs, tests) organized, versioned and under control.

Based on the lecture deck by Andrew Joseph Ramos.

Learning objectives

  1. Describe SCM in the context of the software engineering process.
  2. Identify the models in the configuration management framework.
  3. Describe the activities of a software build and integration process.
  4. Identify automation tools for configuration management.

1 · The basics

Definition

SCM is the process of managing all the pieces and parts (artifacts) produced during software development and support: code, documentation, tests, and more.

It is more than keeping multiple versions. It also involves planning and tools.

Guides: IEEE Std. 1042-1987, NASA's SCM Guidebook. SCM is also a key process in the SEI's Capability Maturity Model (CMM).

SCM activities

  • Understand the policy, process and resulting artifacts.
  • Define the framework used to manage them.
  • Bring in the tools that help.
  • Train the team and make sure the process is followed.

2 · SCM parts

What needs managing depends on the process. A conservative team on a large project may use full waterfall with inspections after each activity. A small Agile team may focus on requirements and coding. The parts fall into three groups:

Artifacts

  • Requirements specification
  • Design specification
  • Source code
  • Executable code
  • Test cases

Hard part: the relationships between them, e.g. requirements and test cases, code and database tables, UI screens and code.

Policy impact

A business decision changes how artifacts are controlled.

Example: letting customers stay on French v2 and update to v2.1 (instead of moving to v3) forces a branching policy.

Process influence

The development and support process shapes how artifacts are managed, such as promotion through test levels.

Try it: promotion through test levels

Code is only promoted after it passes the level below. Once promoted, it is locked so it cannot regress.

    3 · Configuration management framework

    Two main models control all the pieces of software.

    Naming model

    Uniquely identifies each artifact and links related ones. Assumes a unique product name, several artifact types and forms, at least two levels of grouping (release, then version), and multi-country releases.

    Storage and access model

    Corecreate, delete
    Accessview, modify, return
    Control and serviceimport/export, list, set/increment/change, gather/merge, promote

    4 · Build and integration

    Turning source files into executables for a target environment. Two major steps: compile, then link. The build file controls the order: dependency checks, compile, link, generate data files.

     source ──► compile ──► errors? ──yes──► fix + recompile
                │
                no
                ▼
              link ──► executable ──► test / debug / fix
    Build typeWhenNote
    Complete (whole) rebuildOften nightlyLarge systems can take 6 to 7+ hours
    Partial buildDaily fixes during testingNot all code is affected, so use extreme care
    Final buildReleaseFull rebuild for the users' runtime environment, not just the developers'

    SCM planning

    Starts in the early coding phases and produces the SCM plan (SCMP), which can follow IEEE 828 or the organization's own standard. It defines document types and naming, who owns baselines, version and change-control policies, tools, and a configuration management database.

    5 · SCM tools

    Concurrency management

    Handles the same file being edited by several people at once.

    Version control

    Saves every change, logs who made it, and lets you roll back.

    Synchronization

    Check out files or the whole repository, then check changes back in and stay up to date.

    Git

    Free, open-source version control built for speed and all project sizes.

    git-scm.com

    Azure DevOps Server / TFS

    A group of tools that helps a team collaborate and coordinate on building a product.

    Azure DevOps Server

    Recap

    Large projects need their artifacts managed. The framework has two models, naming and storage/access. Combined with build and integration, they let a team manage software pieces and produce different releases.
